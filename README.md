# a-blog cms Passkey プラグイン

a-blog cms の **管理画面ログインをパスキー（WebAuthn）でできるようにする**プラグインです。パスワードの代わりに、Touch ID や Windows Hello などの生体認証でログインできるようになります。

> [!WARNING]
> このプラグインは、Ver. 3.3.0 で本体機能として公式提供を予定している機能のプレビュー版です。本体機能との互換性はないため、3.3.0 へのアップデート後はパスキーの再登録が必要になります。本プラグインの配布およびメンテナンスは、3.3.0 のリリース後に終了を予定しています。

## できること

- 管理ログイン画面 (`/login/`) に「パスキーでログイン」ボタンを自動追加。ID やパスワードの入力は不要です
- 各ユーザーが、ユーザー管理ページから自分のパスキーを登録・削除できます
- 管理者は、サイト全体のパスキー台帳で登録状況を把握し、退職・端末紛失時に失効できます
- パスキー未登録のユーザーには、ログイン時に登録をすすめるモーダルを表示できます
- 認証器名を自動判別して表示します（AAGUID から「Apple iCloud Keychain」「Windows Hello」など）
- インストールだけで完結します。テーマの修正や YAML の編集は不要です

## 動作要件

- a-blog cms 3.2.x
- PHP 8.1 以上（ext-openssl, ext-mbstring 必須、ext-sodium 推奨）
- HTTPS（WebAuthn API はブラウザが HTTP を拒否するため）
- WebAuthn Level 2 対応ブラウザ（最新の Chrome / Safari / Edge / Firefox）

## インストール

リポジトリのディレクトリ構造を a-blog cms にそのまま重ねます。

```bash
# このリポジトリを clone（または zip をダウンロード）して
git clone https://github.com/appleple/passkey.git
cd passkey

# extension/plugins/Passkey/ をそのまま a-blog cms 側にコピー
cp -r extension/plugins/Passkey /path/to/ablogcms/extension/plugins/
```

composer 依存（lbuchs/webauthn）は同梱済みのため、通常は追加の作業は不要です。

その後、管理画面の「拡張アプリ」から **Passkey をインストール → 有効化** してください。サイドバーに「拡張メニュー > Passkey」が現れます。

## 使い方

### パスキーを登録する

各ユーザーが自分で登録します。**ユーザー管理** の基本設定を開くと、２段階認証の下に「パスキー：設定する」ボタンが表示されます。そこから登録・削除ができます。

このボタンとページはプラグインが自動で表示するため、テーマを編集する必要はありません。操作はログインしている本人のパスキーだけが対象で、他人のパスキーを見たり消したりはできません。

### パスキーでログインする

管理ログイン画面に「パスキーでログイン」ボタンが追加されています。押すとブラウザや OS の認証器が起動し、ID やメールアドレスを入力せずにログインできます。

### 登録状況を確認する・失効させる（管理者）

サイドバーの「拡張メニュー > Passkey」に、全ユーザーのパスキー台帳があります。誰がどの認証器をいつ登録し、最後にいつ使ったかを一覧でき、退職や端末紛失の際はここから削除して失効させられます。この画面は管理者のみアクセスできます。

### 登録をすすめるモーダル

パスキーを登録していないユーザーがログインすると、登録をすすめるモーダルが表示されます。

- 表示されるのは**ログインするたびに、直後の画面で 1 回だけ**です。ページを移動するたびに出続けることはありません
- 「設定する」を押すと、自分のパスキー管理ページへ移動します
- 「あとで」（または ESC・背景クリック）で閉じると、一定期間（初期値 30 日）表示されなくなります。この記録はブラウザごとに保存されます
- パスキーを登録済みのユーザーには表示されません

台帳の「設定」ボタンから設定画面を開くと、モーダルの **表示する／表示しない** と **「あとで」の非表示期間（日数）** をブログ単位で変更できます。

## 対象となるユーザー

このプラグインは **管理ログイン（`/login/`）専用**です。フロントのサインイン（会員機能）のパスキー対応は行いません。

| 権限 | パスキーでログイン | パスキーの設定画面 | 登録をすすめるモーダル |
|---|---|---|---|
| 管理者 / 編集者 / 投稿者 | ○ | ○ | ○ |
| 読者 | ― | ― | ― |

読者（subscriber）は a-blog cms の仕様で管理ログインの対象外のため、パスキーの登録・利用はできず、モーダルも表示されません。フロントのサインイン画面に「パスキーでログイン」ボタンが出ることもありません。

なお、万一読者がパスキーを保持していた場合でも、認証後に管理ログイン相当の権限チェック（権限・所属ブログ・IP・端末制限）で拒否されるため、権限の抜け道にはなりません。

> **Note**: `signin_page_auth` を `contributor` に設定している場合、a-blog cms の仕様で投稿者も管理ログインの対象外になります。この場合は投稿者もパスキーを利用できません。

## 設定（任意）

`private/config.system.yaml` で以下を指定できます。いずれも未設定で動作します。

| キー | 内容 |
|---|---|
| `passkey_rp_id` | パスキーを紐づけるドメイン。未設定だと Host ヘッダーから自動決定します。プロキシ経由や複数ドメインで運用する場合は明示を推奨します |
| `passkey_rp_name` | 認証時にブラウザが表示するサイト名。未設定ならサイト名を使います |
| `passkey_user_verification` | 生体認証・PIN の要求レベル（`required` / `preferred` / `discouraged`）。初期値は `preferred` |
